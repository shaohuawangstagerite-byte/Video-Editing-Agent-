# 验证规则

以下规则定义输出视频的技术验收标准。全部通过才算技术验收通过；片段选择、剪辑顺序、画面内容和声音内容等要求须在每次任务中另行明确并验证。

## 必须满足的条件

| 检查项 | 通过标准 | 失败原因示例 |
| --- | --- | --- |
| 输出文件 | 指定路径存在，是普通文件，且文件大小大于 0 字节 | 路径不存在、路径是目录、文件为 0 字节 |
| 可解析性 | `ffprobe` 成功退出，返回的元数据可正常解析 | `ffprobe` 返回非零退出码、元数据格式损坏 |
| 视频轨 | 至少存在一条视频流 | 未找到视频流 |
| 音频轨 | 至少存在一条音频流 | 未找到音频流 |
| 实际时长 | `ffprobe` 返回的容器时长（`format.duration`，单位为秒）可转换为有限正数 | 时长缺失、为 `N/A`、非数字、非有限值或小于等于 0 |
| 时长误差 | `abs(实际时长 - 预期时长) <= 0.5` 秒，包含边界 | 预期 30 秒，实际 30.6 秒，误差 0.6 秒，超过 0.5 秒 |

预期时长必须由任务明确给出，单位为秒，且为有限正数。不得用实际输出时长反向设定预期时长，也不得因为时长缺失而跳过误差检查。

## 验证脚本调用约定

`scripts/validate.sh` 已实现，调用接口如下（替换示例路径和预期时长）：

```bash
bash scripts/validate.sh "outputs/<task-id>/<asset-slug>__<recipe-slug>__v001.mp4" --expected-duration 30
```

从项目根目录（`AGENTS.md` 所在目录）通过 Bash 调用。脚本通过 `validate.py` 使用 Python 标准库解析 JSON，以十进制数比较时长；依赖 Python 3.9+（`python` 命令）及 `ffprobe`，两者必须能从 `PATH` 找到。Windows 使用 Git Bash。

成功时向标准输出写入 `PASS` 及预期、实际、误差等信息；失败时向标准错误写入 `FAIL [检查项]`、目标路径和具体原因，并在第一个失败处退出。脚本不修改被验证的文件。

约定退出码：

- `0`：全部技术验收条件通过。
- `1`：输出验收失败，包括文件不存在或为空、无法解析、缺少轨道、实际时长无效或误差超限。
- `2`：无法正确启动验证，包括参数缺失或无效、预期时长不是有限正数，或缺少 `ffprobe` 等必需依赖。

## 失败说明

失败结果必须指出检查项、具体原因和目标路径，不能只输出“验证失败”。存在可比较的值时，同时提供预期值与实际值，例如文件字节数、轨道类型或时长；时长超限还须提供绝对误差及允许误差。

`ffprobe` 调用或元数据解析失败时，应保留相关原始错误信息；`ffprobe` 非零退出时同时记录其退出码。参数或依赖错误应指出缺少或无效的参数、依赖名称及需要满足的条件。
